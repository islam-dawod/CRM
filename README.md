# CRM ללידים למרפאה — Clinic Leads CRM

מימוש מלא של האפיון שב-`crm.rtf`: מערכת CRM לניהול לידים במרפאת שיניים —
מהרגע שהלקוח משאיר פרטים בפייסבוק או בדף נחיתה, דרך שיחות, WhatsApp, מיילים ותזכורות,
ועד קביעת תור, הגעה בפועל וסגירת עסקה.

> **One Customer → One Card → Everything Inside**

---

## הפעלה

```bash
node server/seed.js
```

```bash
npm start
```

פתחו: **http://localhost:4321**

| דף נחיתה לדוגמה | http://localhost:4321/demo/landing |

> והריצו את השרת מאחורי HTTPS.

## העלאה לאוויר (Live)

הריפו כולל `render.yaml` — Blueprint מוכן ל-[Render](https://render.com) (יש שכבה חינמית, ללא כרטיס אשראי).

1. הרשמה ב-render.com עם חשבון GitHub
2. **New → Blueprint** → בחירת המאגר `islam-dawod/CRM`
3. Render יבקש ערך ל-`CRM_SEED_PASSWORD` — **הזינו סיסמה חזקה משלכם**
4. **Apply** — הפריסה לוקחת כדקה, ומתקבלת כתובת `https://clinic-crm-xxxx.onrender.com`

### מגבלות השכבה החינמית — חשוב לדעת

- **הדיסק זמני.** בכל דיפלוי או הפעלה מחדש `data/crm.db` נמחק והמערכת נזרעת מחדש
  בנתוני דמו. מצוין להדגמה, **לא מתאים לנתוני לקוחות אמיתיים**.
  לנתונים אמיתיים: שדרוג ל-Starter + Persistent Disk ממופה ל-`/data`, והגדרת
  `CRM_DATA_DIR=/data`, וכן `CRM_AUTO_SEED=0`.
- **המופע נרדם** אחרי 15 דקות ללא תעבורה; הבקשה הראשונה אחרי שינה לוקחת ~50 שניות.
- **הכתובת ציבורית.** כל מי שמקבל את הקישור ואת פרטי הכניסה נכנס למערכת.
  אל תשאירו את סיסמת הדמו, ואל תזינו פרטי מטופלים אמיתיים במופע החינמי.

לאחר הפריסה, עדכנו במסך **הגדרות → חיבורים** את כתובות ה-Webhook לדומיין החדש
(פייסבוק ודפי הנחיתה צריכים להצביע על הכתובת הציבורית).

חלופות זהות באופיין: Railway, Fly.io, Koyeb — כולן מריצות `node server/index.js`
ללא שלב build. **GitHub Pages לא מתאים** — הוא מגיש קבצים סטטיים בלבד ולא מריץ Node.

## למה זה בנוי ככה

**אפס תלויות חיצוניות.** אין `npm install`, אין שלב build, אין Docker.
הבסיס נתונים הוא `node:sqlite` (מובנה ב-Node 22.5+), השרת הוא `node:http`,
והממשק הוא ES Modules טהורים שהדפדפן טוען ישירות. זה עונה על הדרישה
"מהירה מאוד" מהאפיון, ומאפשר להריץ את המערכת על כל מחשב עם Node בלי הכנות.

**עברית וערבית מהיסוד.** RTL אמיתי, כל טבלאות היסוד נושאות `name_he` / `name_ar` / `name_en`,
ותבניות ההודעות קיימות בשתי השפות ומסודרות לפי שפת הלקוח.

**Mobile First.** מתחת ל-900px הסיידבר מתחלף בניווט תחתון קבוע, וכל מסך עובד במגע.

## חיבור למערכות אמיתיות

המערכת עובדת מלכתחילה במצב **סימולטור**: הודעות WhatsApp ומייל נשמרות בכרטיס הלקוח
בלי לצאת החוצה. כך אפשר להדגים את כל הזרימה ללא חשבונות חיצוניים.
המעבר לחיבור אמיתי נעשה במסך **הגדרות → חיבורים**, ללא שינוי קוד בשאר המערכת.

| חיבור | כתובת | הערות |
|---|---|---|
| דף נחיתה / טופס / Zapier | `POST /hooks/lead?key=…` | JSON או form-urlencoded; שדות `phone`, `full_name`, `email`, `treatment`, `utm_*` |
| Facebook / Instagram Lead Ads | `GET+POST /hooks/facebook` | GET לאימות (`hub.verify_token`), POST לפורמט `entry[].changes[].value` |
| WhatsApp Cloud API | `GET+POST /hooks/whatsapp` | קולט הודעות, סטטוסי מסירה וכפתורי אישור תור |
| מעקב פתיחת מייל | `GET /t/o/{tracking_id}` | להטמעה כ-`<img>` בגוף המייל |
| מעקב קליקים | `GET /t/c/{tracking_id}?u=URL` | עוטף קישורים במייל |
| אישור תור ללקוח | `GET /confirm/{token}` | דף ציבורי: מאשר / משנה / מבטל |

לשליחה אמיתית ב-WhatsApp: בחרו ספק `cloud_api` ומלאו Phone Number ID + Access Token.
הקוד קורא ל-Graph API ישירות (`server/lib/services.js` → `deliver`).

### דיוק מעקב המיילים

כפי שצוין באפיון עצמו — מעקב פתיחות מבוסס pixel ולכן **אינו מדויק ב-100%**:
חוסמי פרטיות, טעינת תמונות מוקדמת (Gmail/Apple Mail) ולקוחות מייל שחוסמים תמונות
משפיעים על הנתון בשני הכיוונים. יש להתייחס אליו כאינדיקציה, לא כאמת מוחלטת.

## החלטות ופערים

- **הקלטת שיחות (§14)** — יש שדה קישור והנגן עובד, אבל אין חיבור למרכזייה.
  חיבור אמיתי דורש ספק טלפוניה ספציפי, וגם בדיקה משפטית: הקלטה מחייבת יידוע והסכמה,
  ולכן זו החלטה עסקית ולא רק טכנית.
- **סיכומי AI (§15) ועוזר AI (§54)** — מומשו כלוגיקה מקומית דטרמיניסטית מעל בסיס הנתונים,
  ללא מפתח API חיצוני. התוצאה עובדת אופליין, יציבה, ולא שולחת מידע רפואי החוצה.
  אם תרצו מודל שפה אמיתי — הנקודות להחלפה הן `summarizeCall` ב-`lib/util.js`
  ו-`/api/ai/ask` ב-`api/reports.js`.
- **אינסטגרם ב-Inbox (§10)** — הערוץ קיים בסכימה ובסינון; קליטת הודעות דורשת הרשאות
  Messaging נפרדות מפייסבוק.
- **אנגלית (§1)** — מילון UI קיים ומתחלף, אבל שמות הסטטוסים והטיפולים נערכים ידנית בהגדרות.

## אבטחה

סיסמאות מאוחסנות עם scrypt + salt; סשנים ב-cookie מסוג HttpOnly/SameSite=Lax;
כל שאילתות ה-SQL פרמטריות; כל טקסט שמגיע מהמשתמש עובר escaping לפני הצגה;
הרשאות נאכפות בשרת (נציג רואה רק את הלידים שלו, רופא רק את מי שיש לו תור אצלו).
לפני העלאה לאוויר: החליפו סיסמאות, הריצו מאחורי HTTPS, והוסיפו `Secure` לעוגייה
(`server/lib/auth.js` → `createSession`).
